1.1

Core Python

Big idea
Python is your control plane. Loops, functions, and types are the wiring that holds an agent together.
Why it matters
Agent frameworks (LangChain, LangGraph, Pydantic AI) lean on type hints, decorators, and generators. Weak Python = brittle agents.
Step-by-step
  1. Install Python 3.11+ via pyenv. Make a fresh venv for the roadmap.
  2. Write 10 small scripts: FizzBuzz, palindrome checker, word counter, etc.
  3. Refactor each one to use type hints + a function with **kwargs.
  4. Build a decorator @timeit that prints how long any function took.
  5. Convert a nested for-loop into a generator expression; profile both.
Worked example

Object-Oriented Python

Big idea

Why it matters

Error & File Handling

Big idea
Things will fail. Decide *which* failures to recover from and *which* to let crash loudly.
Why it matters
An agent talks to flaky LLM APIs, dodgy PDFs, rate-limited tools. Every external call needs a try/except plan.

  4. Read a CSV of 10k rows and write a JSON file of just the rows with `error == True`.

Working with HTTP APIs

Big idea

Why it matters

1.6

Database Connectivity

Big idea
Agents need state. Conversations, run logs, tool results — they all live in a DB.
Why it matters
Without pooling, every request opens a new TCP connection → 200 ms wasted per request.
Step-by-step

  3. Re-do it with SQLAlchemy ORM (declarative_base, Session).

1.8

Async Programming

Big idea
LLM calls are I/O-bound. Run them in parallel and your latency drops from 6 s to 2 s instantly.
Why it matters
You'll often call 2–3 models, fan out to tools, and log to a DB — all of it should be concurrent.
Step-by-step
  1. Read the asyncio docs intro twice. Then write `async def main():` and call it via `asyncio.run`.
  2. Use asyncio.gather to call 3 fake LLMs concurrently. Time it vs sequential.
  3. Wrap one of them in asyncio.wait_for(coro, timeout=2). Make sure others still complete.
  4. Fire a `create_task(log_to_db(...))` for fire-and-forget logging.
Worked example

async class='kw'>def call_llm(name: str) -> str:
    await asyncio.sleep(random.uniform(0.5, 2.5))
    class='kw'>return fclass='str'>"{name} done"

    results = await asyncio.gather(*tasks, return_exceptions=True)
    print(results)

  • Mixing sync `requests` inside async code — use httpx.AsyncClient instead.
  • Forgetting `return_exceptions=True` will crash the whole gather on one failure.

2.1

What an LLM actually is

Big idea
An LLM is a giant pattern-matcher trained on text up to a cutoff date. It does not 'know' facts — it predicts likely next tokens.
Why it matters
Once you internalise this, hallucinations stop being a mystery: the model is sampling, not recalling.
Step-by-step
  1. Ask ChatGPT 'What is your knowledge cutoff?' — note the date.
  2. Ask it a 'today' question (sports score, stock price). Watch it improvise.
  3. Run the same prompt 5x at temperature=0.7. Note how outputs differ.
  4. Re-run at temperature=0. Now outputs are nearly identical. That's the dial.
Worked example
class='com'># Same prompt, two temperatures

prompt = class='str'>"Write a single haiku about debugging."

        messages=[{class='str'>"role": class='str'>"user", class='str'>"content": prompt}],
        temperature=t,

    print(fclass='str'>"--- temp={t} ---\n{out}\n")

2.2

How an LLM thinks

Big idea
The model sees tokens (not words), in a fixed-size context window, sampling one token at a time.
Why it matters
Tokens cost money. Long context costs accuracy. You'll be making token-budget tradeoffs daily.
Step-by-step
  1. Visit platform.openai.com/tokenizer. Paste a paragraph and count tokens.
  2. Try a non-English language; note the token explosion.
  3. Calculate: if your prompt is 4000 tokens and your reply 800, what's the cost on GPT-4o?
  4. Read the 'Lost in the Middle' paper abstract. That's why putting the answer at the front matters.
Worked example

Big idea

6.1

The context window as working memory

Big idea
Context is the agent's RAM, and it's tiny. Budget it like a memory-constrained microcontroller.
Why it matters
Every wasted token in context is a token of accuracy you didn't buy.
Step-by-step
  1. Print every prompt with `len(tokens_by_section)` for system/context/user.
  2. Cap each section: e.g. SYSTEM=800, CONTEXT=2000, HISTORY=1000.
  3. When over budget, drop sections in this order: old history → low-rerank-score chunks.
  4. Move important info to top/bottom (avoid the middle).
Worked example
BUDGETS = {class='str'>"system": 800, class='str'>"context": 2000, class='str'>"history": 1000, class='str'>"user": 500}
class='kw'>def fit(section, text):
    toks = count_tokens(text)
    class='kw'>return text if toks <= BUDGETS[section] else trim_to_tokens(text, BUDGETS[section])

6.2

Context structure — SYSTEM / CONTEXT / USER separation

Big idea
Three slots, three intents. SYSTEM = rules, CONTEXT = data, USER = ask. Don't mix them.
Why it matters
Mixed-up prompts are why a 'helpful assistant' suddenly writes SQL injection.
Step-by-step
  1. Always emit a 3-block message: system rules, context data, user question.
  2. Surround CONTEXT with <context>…</context> XML.
  3. Never put untrusted user input inside SYSTEM.
  4. Use a @dynamic_prompt to assemble CONTEXT per-request.
Worked example

        {class='str'>"role":class='str'>"system",class='str'>"content":SAFE_SYSTEM},

Big idea

Why it matters

Step-by-step

  2. Strip tool_call/tool_result pairs once the task is done.

6.4

Semantic caching

Big idea
If two questions are semantically the same, serve the cached answer for free.
Why it matters
20–40% of agent traffic is duplicates. Cache hits = pure latency + cost wins.
Step-by-step
  1. Embed every incoming question.
  2. FAISS-search the question store at threshold 0.97 (high-stakes) or 0.88 (FAQ).
  3. On HIT, return cached answer + record a metric.
  4. On MISS, run the full pipeline, then async-write the (q, a) pair into FAISS.
Worked example

6.5

Episodic memory

Big idea
Some Q/A pairs are reusable lessons. Save them, look them up, but don't bypass the agent.
Why it matters
Episodic memory makes the agent feel like it 'learns.'
Step-by-step
  1. After each answer, ask the model: 'EPISODIC: YES/NO?'
  2. Store the YES ones with their q-embedding.
  3. On a new query, fetch top-2 episodes and inject them into CONTEXT.
  4. Never substitute episodes for the LLM run.

6.6

Context compression

Big idea
When history overflows, summarise the old part — keep the recent part verbatim.
Why it matters
Cheaper, faster, and avoids the lost-in-the-middle dropoff.
Step-by-step
  1. Detect history > 3000 tokens.
  2. Take messages older than the last 10. Summarise them with a low-temp call.
  3. Replace them with a single 'SUMMARY: ...' system message.
  4. Manually inspect 10 compressions to make sure nothing critical was lost.
Worked example

6.7

Big idea

7.2

LangGraph fundamentals

Big idea
A graph is just a DAG (or cyclic graph) over functions, with typed state flowing through.
Why it matters
Once the workflow is a graph, debugging becomes 'which node misbehaved?'
Step-by-step
  1. Define a TypedDict state with the fields each node reads/writes.
  2. Build a 3-node graph: plan → write → critique.
  3. Add a conditional edge: if critique fails, loop back to write.
  4. Cap loops with a max_revisions counter in state.
Worked example

8.1

Three-layer guardrail architecture

Big idea
Defence in depth. Cheap fast checks first, expensive smart checks second, tool-level last-mile checks always.
Why it matters
One layer fails. Three rarely do.
Step-by-step
  1. Layer 1: regex + PII detector at the gateway.
  2. Layer 2: LLM-judge for faithfulness on the output, with a safe fallback string.
  3. Layer 3: inside every tool, enforce hard limits (timeouts, query length, top_k).
  4. Log every block reason for monitoring.
Worked example

9.6

Cost & capacity control

Big idea
Cheap by default, expensive on purpose. Cap everything.
Why it matters
A single runaway loop can cost more than your monthly infra bill. Caps + dashboards = sleep.
Step-by-step
  1. Track cache HIT% on the same dashboard as p95.
  2. Route simple intents to a small model; only escalate when needed.
  3. Compress prompts (truncate, summarise) before sending.
  4. Cap max_tokens, max_steps, max_dollars per request.
  5. Run k6 with 100 RPS for 10 minutes. Find where you fall over.
