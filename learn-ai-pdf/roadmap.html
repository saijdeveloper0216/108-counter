PREFACE · How to learn from this guide

Read it like a training plan, not a textbook.

This PDF mirrors the live roadmap at ch-balaji.github.io/ai-engineer-roadmap — but expanded with one concrete example and a short, step-by-step study process for every single module. Every phase is colored so you can find it again in two seconds. Every module fits on one card. Every card answers the same three questions: What is this? · What does it look like in real code? · How do I learn it this week?

01

Block the calendar

Two solid evenings a week (4–6 hrs each) plus one Saturday morning. Twenty-six weeks ≈ 250 focused hours. Less than that and you’ll forget faster than you learn.

02

One module at a time

Read the topic list. Read the example. Then code along — do NOT just watch. The fastest reps: re-type the example, change one input, predict the output, run it.

03

Build the smallest demo

End every module with a 30-line script that proves you understood it. Push it to a private GitHub repo named ai-roadmap/phase-X/module-Y. Future-you will thank you.

04

Ship the capstones

There are three. They are non-negotiable. They are the portfolio that gets you the job. Carve out the listed weeks for them and protect that time like a stand-up meeting.

05

Eval as you go

From Phase 4 onward, every system you build has a tiny golden dataset. Twenty Q&A pairs. Run it on every change. That habit alone separates hobbyists from engineers.

06

Trace everything

Set up LangSmith / LangFuse on day one of Phase 5. When something breaks, your first instinct should be “open the trace”, not “print(everything)”.

eWorked example

A timing decorator that wraps any function and logs how long it took — a pattern you’ll reuse for LLM call latency.

import time from functools import wraps def timed(fn): @wraps(fn) def wrap(*args, **kwargs): t0 = time.perf_counter() out = fn(*args, **kwargs) print(f"{fn.__name__}: {time.perf_counter()-t0:.3f}s") return out return wrap @timed def chunk_text(s: str, n: int = 500) -> list[str]: return [s[i:i+n] for i in range(0, len(s), n)]
sStep-by-step (2 evenings)

  2. Read the official tutorial sections 3–5 (docs.python.org) — just those.
  3. Type out 10 list comprehensions and 5 dict comprehensions by hand. No copy-paste.
  4. Write the @timed decorator above from scratch, then wrap a function that sleeps.
  5. Add type hints to every function you wrote today and run mypy . with no errors.

eWorked example

A resilient client that retries on 429/5xx with exponential backoff — the bare minimum every LLM caller needs.

import requests from tenacity import retry, wait_exponential, stop_after_attempt @retry(wait=wait_exponential(multiplier=1, max=30), stop=stop_after_attempt(5)) def fetch(url, headers): r = requests.get(url, headers=headers, timeout=10) if r.status_code in (429, 500, 502, 503): r.raise_for_status() return r.json()
sStep-by-step (1 evening)
  1. Sign up for a free API (e.g. openweathermap.org) and grab a key.
  2. Make a GET call with requests; inspect r.status_code, r.headers, r.json().
  3. Install tenacity; wrap your call with the retry decorator above.
  4. Simulate a 429 by hitting the endpoint 50 times in a tight loop. Watch the backoff.
  5. Always pass timeout=. Forgetting it is the #1 cause of frozen prod jobs.

eEnd-state example

Three “LLMs” called in parallel, the slow one times out, logging fires without blocking the response — exactly the phase’s success criterion.

import asyncio async def call_model(name, delay): await asyncio.sleep(delay) return f"{name} done" async def log_async(msg): print("LOG:", msg) async def chat(): tasks = [ asyncio.wait_for(call_model("gpt", 0.3), timeout=1), asyncio.wait_for(call_model("claude", 0.5), timeout=1), asyncio.wait_for(call_model("gemini", 5), timeout=1), ] results = await asyncio.gather(*tasks, return_exceptions=True) asyncio.create_task(log_async(results)) # fire and forget return [r for r in results if not isinstance(r, Exception)] print(asyncio.run(chat()))

OUT OF SCOPE · What NOT to learn (yet)

Four delicious rabbit holes to avoid.

Time is the constraint. These topics are wonderful — and they are not on the critical path to becoming an agent engineer in 2026. Learn them after this roadmap, not during.

Fine-tuning foundation models

RAG, prompting, and tool use solve 95% of business problems faster, cheaper, and with no infra overhead. Fine-tuning earns its weight only when you have a narrow domain, lots of clean labelled data, and prompting has hit a wall.

When to revisitStart with LoRA + a 7B open model (Llama, Mistral, Qwen) on a single A10/L4 once you have a real motivating use case.

Voice agents

A whole sub-discipline — STT, TTS, turn-taking, latency budgets, barge-in. Worth its own track, not a side note. You can graft it onto any agent you build in this roadmap later.

When to revisitOpenAI Realtime API, Deepgram + ElevenLabs + LiveKit, or pipecat — after you’ve shipped one text agent.

ML fundamentals from scratch

Gradient descent, backprop, transformers from first principles — lovely to know, not required to be an excellent agent engineer in 2026. Karpathy’s series is there when you’re curious, on weekends.

When to revisitAndrej Karpathy’s “Neural Networks: Zero to Hero” + the “Let’s build GPT” video, on Saturday mornings.

Frontend frameworks

You need enough Next.js / Streamlit / Tailwind to ship a chat UI for capstones. Beyond that, partner with a frontend engineer or a design system. Don’t get lost in framework wars.

When to revisitStreamlit for internal tools; Vercel AI SDK + Next.js when you need a real product UI.
